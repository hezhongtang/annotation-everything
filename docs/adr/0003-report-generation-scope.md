# 内置基础报告生成范式，允许替换生成方法

AE 的默认承诺是：使用者只安装 AE，就能从原始材料得到达到最低要求的可审阅初稿；已有生成技能的使用者，可以继续使用自己的方法。AE 因此需要随技能提供基础生成范式和共用交付要求，让默认生成路径可用，并使不同生成方法产出的报告有共同的验收依据；仅提供外部仓库链接无法满足这一承诺。

生成推理、材料读取编排与内容判断由宿主 Agent 执行；AE 提供随技能发布的流程、基础样式、产物约定、确定规则检查和核验清单，不嵌入新的模型服务。

首版接收文本、PDF、Word、表格等常见办公材料。读取失败、提取不完整或无法核实的部分须明确列出缺口；未读到的内容不能视为已核验。默认使用内置范式，用户指定或任务需要扩展时使用外部生成技能，两者遵守同一套交付要求。

生成前从已有对话和材料明确用途、读者、核心问题、篇幅或时长，以及讲稿需求，只补问影响结果的缺项。讲稿需求尚未说明时先询问，已有明确选择时直接沿用。需求明确后连续生成初稿，再进入审阅。

首版默认交付逐页 HTML，报告章节与叙述顺序按用途安排，并提供基础视觉样式。讲稿按用户选择生成。外部技能可以提供其他风格，以及 PPTX、PDF 等额外交付形式。

验收采用程序检查与内容、视觉核验相结合的方式。格式、页码对应、引用记录等确定规则由程序检查；Agent 按统一清单核对结论依据、结构与页面效果，记录结果及无法检查的部分。未执行的检查不能计为通过，程序通过只证明对应规则通过。

「初稿生成完成」与「报告可交付」分别判定。初稿内容可读、结构完整、能够进入审阅，且已知缺口明确列出，即可判定初稿生成完成；报告可交付还须通过规定的程序检查与内容、视觉核验，影响核心结论的材料缺失、口径冲突或未经核实的数字会阻止通过交付验收。

内置范式与外部生成技能都须使关键结论、数值及影响判断的事实可追溯。依据应定位到原始材料的页码、段落、单元格等位置，计算结果保留计算口径，并核对来源是否支持报告中的表述。找不到依据的内容标为「待核实」，按其是否影响核心结论判断能否通过交付验收。

报告显示必要引用，完整核验记录保存在原始材料旁，交付时提供核验摘要。核验记录包含关键内容的来源依据、计算口径、核验结果、实际采用的技能或工具名称及可得版本信息、本次不可用的能力；交付摘要说明实际采用的方法和能力缺口。扫描到的候选技能不等于已启用或已调用。记录按材料本身的存放与隐私要求管理。

已有报告保留直接进入审阅的入口。新生成报告或用户明确要求整体核验时执行完整验收；普通改稿检查受影响内容，并更新已有的相关核验记录，全量勾稽仍按用户选择执行。

上述产品边界与交付原则已确认，相关生成与验收能力尚待实现。实现依据见[报告生成规格 #69](https://github.com/hezhongtang/annotation-everything/issues/69)及其六项子任务；具体检查清单、核验记录格式及外部技能的接入细节随对应任务落实。
