# 服务连接与接收会话分别确认

本地服务可在多个 harness 之间复用，启动服务的会话、正在等待的进程和处理署名都不能证明批注会交给谁。接收方以 harness 和会话标识共同确定，复用现有审阅级 `.agent-binding.json`：Codex 桌面继续使用事件适配器，其他 harness 可绑定等待适配器；页面分别展示服务连接与接收会话。

绑定在停止等待后保留。更换或解除绑定必须显式执行，初改中或复核中的批次须先收尾。绑定变更、批次领取和页面提交在批注文件锁内校验，旧等待者和携带旧绑定的提交不能沿用新接收方。改绑后重启服务，避免页面声明的接收方与运行中的事件钩子不一致。我们选择这套规则，而非按等待进程抢占或断线后自动切换，因为短暂断线不应改变批注归属。

旧审阅未绑定、旧服务不提供身份、绑定无效和服务断开都明确显示为未确认；只有绑定有效时才显示确定身份。事件适配器不以等待进程的有无判断聊天在线，桌面接受投递与聊天实际接手仍分别记录。这里约束受支持工具的操作，不把本机文件所有者隔离成安全边界。
