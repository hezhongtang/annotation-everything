# 审阅总览可以跨审阅读取、归档、启动和停止

> 2026-11 更新：本文否掉的「单独的总览服务」选项后来在无审阅运行时缺入口的前提下被重开，见 ADR 0008（独立总览首页）；本文其余结论（跨审阅读取、归档标记在审阅目录、代为启动与安全边界）继续有效。

原先一份审阅的服务只管它托管的那份审阅。用户要在一个页面里看到同一工作区的全部审阅、跳过去、把不再推进的归档，所以我们让任一审阅的服务都能提供审阅总览：按审阅台账列出同一工作区的审阅，现场读每份的审阅目录和报告旁的核验记录；可以改写别的审阅目录里的归档标记；可以按审阅标识代为启动一份已停审阅的服务，再在新标签页打开它的专属端口地址。

这样做时，以下边界不变：写操作照旧要求同源 Origin 和 JSON Content-Type；代为启动只接受台账里登记过的审阅标识，不接受路径、端口或命令；服务仍只暴露 index.html 与 `/api/*`，审阅总览是 index.html 里的一个视图。归档标记存在审阅目录里，台账仍只存标识、路径和端口（ADR 0001）。总览里只显示相对工作区的路径，不显示本机绝对路径，这是对 ADR 0001「对照页里不写本机路径」的放宽。

## Considered Options

- **单独的总览服务**（`serve.py overview`，用自己的固定端口）：没有审阅在运行时也能打开，但要多维护一种服务和一个端口。我们改为从任一审阅进入，命令行仍可用 `serve.py list`。
- **只读总览，已停的审阅给出启动命令**：不会由网页触发进程启动，但「跳转」要多走一步手动操作。
- **归档标记存在台账里**：读取快，但违背「台账只是索引」；审阅目录搬家或复制后，标记不会跟着走。

## Consequences

- 一份审阅的页面能看到同一工作区里其他审阅的审阅名、相对路径、摘要和核心问题。它们属于本机同一个用户，所以这里不把审阅之间的隔离当作安全边界（与 ADR 0004 相同）。
- `serve.py check` 要覆盖新增的总览、归档和代为启动接口，验证伪造 Host / Origin 的请求会被拒绝，以及传入台账外标识时不启动任何进程。
- 归档不停止服务。被归档审阅的对照页刷新后会显示「已归档」横幅，批注和提交照常可用。
- 停止请求按审阅标识和所选范围查台账，并核对目标运行服务的标识、审阅目录、实际端口和进程。异源目标通过本机 HTTP 进入同一停止生命周期。目标对照页在其同源服务登记和确认补传，托管总览的服务只接收停止状态。
