# 重开独立的总览首页：无审阅运行时的总览入口

ADR 0006 否掉过「单独的总览服务」，当时没有审阅运行就打不开总览，用户只能翻终端历史或先跑 `serve.py list` 再手动启动；那条否决针对的是「只为省一个入口而多养一种服务和端口」。现在入口本身成了缺口：宿主审阅一停，总览页跟着消失；Agent 也需要一个不依赖某份审阅的地址来代启动审阅、查看接收状态。所以我们重开这个选项，用 `serve.py overview` 打开独立的总览首页（overview home）：一个不绑定任何审阅的服务，只服务总览视图。从任一审阅对照页进入总览的旧路径保持不变（ADR 0006 的其余结论继续有效）；总览从此有两种宿主，页面能力一致。

这样做时要付出的维护代价与边界如下。

## Considered Options

- **维持 ADR 0006（从任一审阅进入）**：不多养服务，但「零运行审阅」时没有入口；宿主审阅停止会连带中断正在查看总览的人。
- **独立总览首页（本 ADR）**：补上无审阅入口，代价是多一种服务形态、一个保留端口和它的生命周期管理；这些代价用下述边界约束住。
- **把首页寄生在台账目录的常驻进程里**：不需要新命令，但引入开机自启式的常驻组件，违背「不装成常驻或开机自启」的约定。
- **每次临时起一个无端口的本地页面**：不占端口，但没有稳定地址可收藏，也无法跨标签页持有运行状态。

## Consequences

- **单实例与复用**。每份台账只运行一个总览首页。相同启动配置（规范化的 `--under`、显式临时端口、默认语言、钩子参数，以及启用钩子时的工作目录）复用当前实例及其地址；配置不同则非零退出，提示退出当前首页后再启动。`--no-open` 只影响本次调用是否打开浏览器。
- **端口协调**。首页的保留端口记录独立存放在台账目录，分配与认领和审阅共用台账写锁；首页避开已有审阅的专属端口，新版审阅服务的自动分配、显式认领与顺延也避开首页保留端口，首页退出后同样适用。保留端口被占用或遇到旧版已登记的冲突端口时，首页本次临时顺延并警告；`--port` 只影响本次地址。退出时清理运行状态，保留端口记录。这与 ADR 0001「台账只存索引」一致：首页文件（页面、运行状态、日志、端口记录、锁文件）都在台账目录，不算审阅数据。
- **`--under` 范围**。首页默认范围是本机台账全部审阅；`--under` 沿用 `serve.py list --under` 的目录包含关系。列表、启动、归档与取消归档、单份或批量停止、失败重试都在服务端核对同一个有效范围；按工作区划界的 `scope=workspace` 在首页上返回 400 并提示改用 `--under`。对台账内但超出范围的目标返回稳定原因码，拒绝启动和写入。
- **宿主边界**。首页不登记成审阅、不写审阅清单、不迁移旧数据。审阅专属接口（批注读写、分析、交接、停止生命周期、接收方绑定写路径）在首页上显式拒绝，返回稳定原因码；首页自身没有停止生命周期，用 Ctrl+C 退出。健康检查报告宿主种类和宿主标识，写操作要求对应的宿主标识请求头，沿用 ADR 0006 的全部安全门（只绑 127.0.0.1、Host 校验、写操作同源 Origin + JSON Content-Type、无 CORS 头、只暴露 index.html 与 `/api/*`）。代为启动沿用 ADR 0006 的通道与「台账外标识不拉起进程」的哨兵自检。
- **更新与卸载边界**。首页运行期间沿用服务的更新锁：`update.py` 拿不到排他的副本锁时会报告有服务在运行并推迟更新，先退出首页再更新。`ae.py uninstall` 识别正在运行的首页并拒绝卸载，`--stop-servers` 核对进程身份后与审阅服务走同一条停止路径；审阅目录任何情况下不动。体检的审阅服务计数与孤儿修复跳过首页。
- **能力公布**。新版 `serve.py --help` 公布 `overview` 子命令，供新版工作流用命令式检查探测实际调用的技能副本；副本缺失该能力时检查以非零状态结束，并给出指向包含本功能的技能副本的升级指引。
