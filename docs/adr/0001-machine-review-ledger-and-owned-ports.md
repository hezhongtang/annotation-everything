# 本机审阅台账与专属端口

同一台机器上常有多份审阅（甚至同一个项目里就有几份）。端口和浏览器暂存都是整台机器共用的：暂存按来源 `127.0.0.1:端口` 隔离，一份审阅的服务换了端口，旧标签页里没补传的改动就再也到不了它。所以我们在审阅目录之外放一个本机级的审阅台账（`~/.annotation-everything/`，测试和 eval 用 `AE_HOME` 改位置），按审阅标识登记审阅目录和专属端口：审阅第一次启动服务时分到端口，此后归它独占，停了也不让给别的审阅，只有 `forget` 才释放。这是「审阅的一切都在审阅目录里」的唯一例外，所以台账只存标识、路径、端口，审阅名等业务信息仍只在审阅目录里，列出时现场读取。

## Considered Options

- **项目级台账**：skill 没有「项目根」概念，而且端口冲突是跨项目的，项目级台账看不到。
- **只扫描、不建台账**：无状态，但必须给出根目录，也没法给审阅保留端口。
- **按顺序找空闲端口（原做法）/ 优先回到上次的端口**：一份审阅停掉后，它的端口会被别的审阅拿走，旧标签页因此长期显示「服务不匹配」，暂存也卡在旧来源下。

## Consequences

- 专属端口被其他程序占用，或者显式传了 `--port` 时，只临时顺延，并警告用户这次的暂存不会跟到新地址；要换专属端口，用 `--claim-port`。
- 对照页里不写本机路径。「服务不匹配」提示给出按标识启动的命令（`serve.py <标识>`），由台账查出审阅目录。
