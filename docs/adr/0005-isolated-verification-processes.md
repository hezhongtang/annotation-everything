# 在原资源锁内并行执行已确认独立的验证

#49 / #57 的完整验证目标要求缩短反馈时间，同时保留全部检查。单进程测量显示，测试用例累计执行并非必须全部串行：一部分模块仅操作各自的合成目录，浏览器场景也已声明独立审阅目录、端口与上下文。因此在既有验证组和资源锁内，采用最多 3 个 POSIX 子进程执行已审查的独立任务；不引入新的测试框架或互斥协议。

完整单元仍先取得 `host-state`。会读取宿主进程或启动真实 `serve.py` 的单元模块都进入唯一串行任务；只有显式允许且没有敏感资源声明的模块可以独立执行。未知模块默认进入串行任务，自定义套件、少量模块和已存在其他线程时保留原执行方式。完整浏览器整组仍持有 `host-state`，每个场景各自拥有进程、浏览器、合成 HOME、台账与技能目录；新增场景未明确声明 `parallel_safe=True` 时，整组恢复串行。

fork 子进程继承实际锁描述符，并各自建立登记的进程组，父进程提前退出不会使尚在执行的任务失去锁保护。中断先执行任务的收尾，再回收本次登记的子进程。原始退出码、失败、未完成结果和不匹配清单均保留，不能汇总成通过。组墙钟、进程累计执行与逐用例时间分开记录；执行方式进入环境比较键。`AE_VERIFY_SERIAL=1` 恢复串行，原来的直接 `unittest` 命令也保留。

本决定替代 [ADR 0002](0002-unified-verification-entry.md) 中「不把纯逻辑测试拆成独立进程」的执行细节；统一入口独立于产品 CLI、只使用标准库、保留证据和退出码的决定继续适用。

异常任务退出后，父级仍回收登记进程组中的受控服务；取消收尾保留任务已写出的部分记录。敏感单元在原进程执行，使用分离会话的执行器测试不进入独立任务。
