# macOS Word 任务窗格原型实测

2026-11-27 在 macOS 26.7.3（25G342）、Microsoft Word 16.115.2 上使用合成合同 A 和 B。两份文件均名为 `contract.docx`，保存在不同目录，正文分别标有 `AE-214-A`、`AE-214-B`。复现步骤见[原型说明](word-taskpane-prototype.md)。

| 检查 | 实际观察 |
| --- | --- |
| 打开原稿 | Word 打开 A，状态栏显示第 1 页、共 2 页。修订已开启，Review → Tracking → Display for Review 显示 All Markup。正文显示“收件方式为邮件，应于五日内回复。”，表格单元格另有“应于五日内回复”。第一页末段包含“本合同自签收即生效。”。 |
| 既有讨论 | Word 原页显示乙的评论“此处的五日是否足够完成复核？”及甲在同一线程的回复“收到，请按验收安排复核时限。”。 |
| 固定来源与专属端口 | A、B 的浏览器审阅分别在 127.0.0.1 的 43911 和 43912 端口同时运行。固定来源 43821 用 A 启动。终端 TLS 客户端验证证书后读取任务窗格得到 HTTP 200。 |
| 接口核对 | 在两份审阅都运行时，使用 A 的绑定码和 A 的文档位置调用绑定接口，得到 A 的审阅名和两条合成建议。使用同一绑定码和 B 的文档位置得到 HTTP 409（bad-binding）。 |
| 端口占用 | 保持 A 运行，尝试在固定端口启动 B，进程以状态码 2 退出，报告 Fixed port 43821 is already in use。A 随后仍能完成绑定请求。 |
| 证书 | 使用仅含 127.0.0.1 IP SAN、有效期一天的自签名叶证书。在当前用户钥匙串中将 SSL 信任限定到 127.0.0.1。macOS 的 `security verify-cert` 验证成功。 |
| 侧载目录 | Word 用户容器最初没有 `wef` 目录。从终端创建时 macOS 返回 Operation not permitted。Finder 正常打开 Word 的 Documents 目录并能创建 `wef`。 |
| 清单发现 | 在 Finder 复制清单后退出 Word，重新打开 A。“开始 → 加载项”下的 Developer Add-ins 显示“AE 本机审阅”及本机服务提供的图标。用户在菜单手动激活一次后，Home 功能区出现“打开审阅”；再次开文档可直接从此按钮进入。 |
| 文档位置 | 同一份 A 的 Word 窗口第一次显示以 `/private/tmp` 开头的本地 URL，经 Finder 重开后显示 `/tmp`。固定来源会核对解析后确实指向同一文件的 macOS 系统路径别名。 |


## Word 内的连接与回读

Word 访问固定 HTTPS 页面时会附加 `_host_Info` 查询参数。最初窗格报告 “A problem occurred while trying to reach this add-in”。允许同一页面带宿主查询参数后，Word 加载了绑定表单。请求日志记录了 TLS 1.3 和页面 HTTP 200。

实测发现，页面采用 `Referrer-Policy: no-referrer` 时，WebKit 发起的绑定 POST 同时带有 `Origin: null` 和 `Sec-Fetch-Site: same-origin`，接口以 403 拒绝。改用 `Referrer-Policy: same-origin` 后，Word 发送 `Origin: https://127.0.0.1:43821`，返回 HTTP 200。侧栏显示匹配的审阅名称和两条建议。Office.js 报告的平台为 Mac，内部版本为 16.115.1122.2，跟踪模式为 TrackAll。

在 B 合同的 Word 窗格中点击“读取选区与正文修订”，再复制完整回读。下表为 Word 返回的实际值，五条均署名甲。

| 类型 | 修订文字 | 范围可见文字 | 范围 Original | 范围 Current |
| --- | --- | --- | --- | --- |
| 删除 | 传真 | 空串 | 传真 | 空串 |
| 新增 | 邮件 | 邮件 | 空串 | 邮件 |
| 删除 | 及备用件 | 空串 | 及备用件 | 空串 |
| 段首新增 | 共同 | 共同 | 空串 | 共同 |
| 紧随段首新增的删除 | 分别 | 空串 | 分别 | 空串 |

在 B 的“所有标记”视图中，页尾原段位于第一页。应用长替换后，Word 回读到增删，选区移至第二页，保存前状态栏即显示 Page 2 of 2。

## 原批注范围内改字的裁决对照

A、B、C 都有同一处表格“五日”、乙的批注、甲在该线程的回复，以及正文另外五条甲的旧修订。实验使用原型开发版本，分别在独立副本中用 Word 自身的 Accept / Reject 处理表格改动，保存后检查表格文本、原批注、回复父子关系及锚点。下表记录历史试验，交付行为见表后。

| 试验 | 原生操作 | 收件人结果 |
| --- | --- | --- |
| A | 在原批注范围整词把“五日”改成“七日” | 原位回读到待审新增和删除，正文重复的“五日”保留。接受后表格为“七日”，拒绝后为“五日”，两份的旧线程均丢失。 |
| B | 仅替换“五”为“七”，保留“日” | 接受副本保留了乙的主批注和甲的回复。拒绝副本丢失整个线程。两份均保留正文原词及甲的五条旧修订。 |
| C | 在批注内部先插入“七”，重新定位并删除“五” | 写入后两个修订均在主批注和回复的范围内，Word 保存了原讨论。独立副本仅拒绝“七”的插入并立即保存时，剩余“五”的删除尚待审，两个批注及范围已消失。 |

2026-11-27 确认的验收口径为：与原线程交叠的建议保留在侧栏，写入前提示冲突；正常写入另用无批注覆盖的文字验收。Word 的评论接口可以回读锚点、作者、线程标识和回复，未提供可将既有线程迁至另一正文范围的操作。[Word.Comment](https://learn.microsoft.com/en-us/javascript/api/word/word.comment) · [可更新的评论属性](https://learn.microsoft.com/en-us/javascript/api/word/word.interfaces.commentupdatedata)

九项标准的逐条状态、同一份样本与收件人操作见[桌面 Word 收件人验收](word-recipient-acceptance.md)。交付版本在同一表格第二格的“五日”上实测拦截了替换。原词、乙的批注和甲的回复都保留。第一格的独立修订及收件人接受、拒绝、继续回复和重开结果见[收件人验收记录](word-recipient-acceptance.md)。

## 批量写入与段落身份

同一批中勾选一条合法正文建议及一条覆盖原批注的表格建议时，窗格在写入前提示冲突。取消冲突项后重新选择，Word 把正文两处改为“收件方式为邮件，应于七日内书面答复。”，同时把第一格改为“交付异议”。两项正文均回读为已写入。第一格实际有新增“交付”及删除“验收”，但 Mac 的段落修订集合只返回删除项，侧栏保守地报告需核对。通过全文修订集合能够同时读到二者，并核对各自的范围属于该选区。补充的回归用例要求目标段外的同名修订不能用于确认本段写入。

同一次 Word 调用中，单独导出正文段和单元格段会为段落重新分配标识。导出整篇正文保留了磁盘原件的两个原始标识。该合同的 Word 段落集合共有 33 段，全文 XML 导出有 34 段，两边都只有一张表。窗口锁屏前实际观察到严格计数检查拒绝了写入。修复通过源文件末段标识、原生末段文字和额外段的结构核对导出的空白末段；代码的定向回归与最后一次桌面复验分别登记。
