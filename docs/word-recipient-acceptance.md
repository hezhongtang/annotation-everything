# 桌面 Word 收件人验收

2026-11-27 在 macOS 26.7.3（25G342）、Microsoft Word 16.115.2（Office.js 报告 16.115.1122.2）验证了下表列明的操作。审阅人使用打印布局、所有标记、TrackAll。Windows 桌面及独立未安装 AE 的收件人环境本轮尚未独立验收。[收件人场景 #221](https://github.com/hezhongtang/annotation-everything/issues/221) · [父规格 #213](https://github.com/hezhongtang/annotation-everything/issues/213)

表格第一格「验收异议」没有批注，供审阅人写入「验收」→「交付」并交付收件人。第二格「应于五日内回复」的「五日」已有乙的批注和甲的回复，与建议交叠。Word 的历史试验表明，即使写入当时讨论还在，拒绝修订也可能删除整个线程。当前口径要求这一格提示冲突、保留建议和讨论。[三种替换方式的 Word 实测](word-taskpane-macos.md#原批注范围内改字的裁决对照)

## 九项验收矩阵

「部分通过」只覆盖该行写出的实测动作。「待验」指尚未执行。「环境阻塞」指已知缺少执行条件。「失败」保留实际所得与预期的差异。两端各自在 Word 中保存、关闭和重开后登记结果。

| #213 标准 | macOS Word 实际观察 | Windows 桌面 Word |
| --- | --- | --- |
| 1 打开旧稿 | 部分通过。打开两页合同，正文与表格各有一个「应于五日内回复」。Word 回读甲的五项修订，乙的原评论与甲的原回复可见。仅查看后保存重开，在同一原件逐项核对的结果待验。 | 环境阻塞，本轮无 Windows 宿主。 |
| 2 送审旧痕迹 | 第 1 批只选正文第 4 段，原文为「收件方式为传真，应于五日内回复。」，改后为「收件方式为邮件，应于五日内回复。」绑定会话领取后返回两条建议，Word 窗格显示建议。第 2 批只选第 9 段的「五日」并勾乙的线程，批次中可核对乙的原话、甲的原回复、署名和范围。 | 待验，用相同段号和引语比对。 |

| 7 选区与保护 | 部分通过。当前实现拒绝第二格交叠建议，实机确认原范围、原讨论在位。两份同名 A/B 用同一绑定码向绑定接口核对时，B 返回 409。旧修订同段其他位置、外改、只读、保护、签名、跟踪不可启用及受限宿主的实机结果逐项待验。 | 待验，分别记录拒绝原因及写前写后原文。 |

## 重建样本与绑定

1. 从仓库根目录执行以下命令。选择尚未使用的输出目录。可在每个平台从同一份未打开的生成件复制，也可在同一代码版本重新生成。PowerShell 使用 `py -3` 代替 `python3`，路径可用 `"$env:TEMP/ae-word-221"`。

   ```sh
   DEMO=$(mktemp -d)
   python3 fixtures/docx/make_word_native.py --prepare-reviews "$DEMO"
   python3 fixtures/docx/check_word_recipient.py "$DEMO/A/contract.docx" --expect original
   ```

2. A、B 两个目录各有 `contract.docx` 和审阅目录 `review`，文内编号含 A 或 B。正文当前为「收件方式为邮件，应于五日内回复。」。甲留有删除「传真」、新增「邮件」、删除「及备用件」、新增「共同」、删除「分别」五项。表格第一行第二格中，乙问「此处的五日是否足够完成复核？」，甲回复「收到，请按验收安排复核时限。」第一页末段为「本合同自签收即生效。」分页取 Word 原页的观察值。
3. 保留一份未编辑的基准 DOCX。审阅阶段按[启动与重连](../skill/annotation-everything/references/word-native.zh-CN.md)在本机打开原件、绑定对应审阅和接收会话。只有审阅端需要本机服务、受信任的环回 HTTPS 证书、Word 清单和可加载的 Office.js。将审阅人和收件人的系统、Word 版本与内部版本、布局、显示标记、跟踪开关分别记在结果表。
4. 在正文第 4 段预览并提交原／改后文字与修订，领取并返回两条建议。再在第二格单选「五日」，预览中勾选乙的原线程，提交并领取。核对提交中只含选区及该线程。返回建议后先刷新、定位；此时检查 Word 旧修订计数和两个「五日」。输入、绑定和查看阶段都要记录这一基线。
5. 在第二格尝试将「五日」改为「七日」。记录侧栏未写入的原因及待处理建议，再点原词核对乙、甲、引用范围和两处「五日」。在第一格选「验收异议」并送审，接收方使用下列 JSON 返回建议。勾选本批建议并点击「将所选建议写为修订」。核对原页第一格的删除「验收」和新增「交付」、署名、未勾的建议、正文同名词与受保护的第二格。保存并关闭原件，再重开到相同位置核对。

   ```json
   [{"n":7,"from":"验收","to":"交付","reason":"在无批注的第一格明确交付环节。"}]
   ```

6. 从已保存的同一个待审件复制 `accept.docx` 和 `reject.docx`，另留该待审件作基准。将两份副本作为普通文件交给收件人。在另一份新生成的审阅里做多选、改页尾、中断及撤销，避免干扰两份收件副本。批号随该审阅历史递增，JSON 的 `n` 从零开始。

## 未安装 AE 的收件人

收件人只需桌面 Word 和两个 DOCX。在未安装 AE 或加载项的设备上打开文件，选择打印布局和「审阅 → 所有标记」，记录当前跟踪开关。

1. 打开 `accept.docx`，在表格**第一格**的「验收」／「交付」上逐项使用 Word 的「接受此修订」。一处替换可能显示为多个插入和删除，只处理这一格本轮的修改。确认第一格为「交付异议」，第二格和正文均为「应于五日内回复」。在第二格选「五日」，核对乙的原话、甲在同一线程内的原回复，向**该线程**追加「合成收件人已核对接受副本。」。保存、关闭并重开。
2. 打开独立的 `reject.docx`，对第一格本轮修订逐项使用「拒绝此修订」，得到「验收异议」。再次核对第二格与正文的「五日」及两位原作者，在乙的同一线程内回复「合成收件人已核对拒绝副本。」。保存、关闭并重开。
3. 在两份重开件中分别确认第一格没有本次待审条目；甲的五项旧修订仍待审；乙的批注高亮仍指向第二格「五日」，且同一线程保留甲的原回复、本轮已存在的回复和各自的收件人回复。截取第一格裁决后文字、原线程及修订窗格，记入收件人环境和文件名。若只在开发机关闭 AE 窗格操作，请记录为「同机 Word 原生裁决」，单独保留未安装 AE 设备的待验项。
4. 将保存件带回验收机，用标准库只读复核下列文件。它核对保存件中的文字、修订、旧作者、原批注的实际引用范围和回复父子关系。拒绝后的文字与初始文字相同；原先是否确有待审修订，需要待审件、Word 裁决操作和重开件三处证据。工具无需交给收件人。

   ```sh
   python3 fixtures/docx/check_word_recipient.py tracked.docx --expect tracked
   python3 fixtures/docx/check_word_recipient.py accept.docx --expect accepted --reply '合成收件人已核对接受副本。'
   python3 fixtures/docx/check_word_recipient.py reject.docx --expect rejected --reply '合成收件人已核对拒绝副本。'
   ```

## 安装与复验记录

Mac 手动侧载后，`--open-word` 已打开目标原件。Word 返回的 `/tmp` 本地路径别名校验成功，从功能区展开侧栏后可绑定。受信任环回来源一次服务一份审阅。实测在单个窗格阻断 Office.js 后，页面显示恢复提示并禁用绑定；恢复正常页面并重新加载，绑定成功。完整断网、冷缓存、Windows 侧载、组织分发及 Marketplace 仍待验。[安装、CDN 与分发记录](../skill/annotation-everything/references/word-native.zh-CN.md#启动故障与分发)

每次复验按平台为每个动作留一行。登记日期、代码版本、宿主系统与 Word 版本、设备角色及 AE 是否安装、视图与跟踪状态、源文件与保存件标识、操作、预期、实际、结果、截图或录屏位置。失败时登记复现文件、修复版本和相同平台的复验结果。归档范围仅限合成材料；截图可裁去本机路径、登录账户和绑定码。
