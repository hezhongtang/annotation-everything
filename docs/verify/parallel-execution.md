# 验证组内的有界进程执行（#57）

`verify.py` 使用现有 `unittest` 和浏览器场景注册表执行完整检查，最多同时启动 3 个独立验证进程。资源敏感组仍先取得原有的 `host-state` 锁，跨 worktree 与独立 checkout 的互斥、锁等待计时与超时语义保持不变。`verify_parallel.py` 负责进程调度和回收，不创建新的资源锁。

## 单元范围

`_unit-runner` 先完整发现套件。只有标准 `TestSuite`、至少 8 个模块、没有其他运行中的线程、且未指定串行时，才使用进程隔离。`PARALLEL_UNIT_MODULES` 是显式允许列表；资源声明优先，任何敏感模块与未分类的新模块都在唯一串行任务内运行。每个进程各自持有合成 HOME、台账和技能目录，不能共享可变的用户目录。

入口 fixture 只复用不变的合成 Git 初始历史，每个用例仍有独立工作树、`.git` 和锁目录。HTTP 用例只缩短测试内 `serve_forever` 的退出检查间隔，不改变产品轮询、请求超时、清理升级参数或安全断言。CLI 语言测试使用合成进程表；真实进程盘点、服务生命周期和清理边界仍在原资源敏感模块中验证。

## 浏览器范围

完整模式仅在全部场景明确声明 `parallel_safe=True` 时并行。每个场景拥有进程、Chrome、临时材料与全部合成用户目录；父进程登记的目录所有权不会被子进程继承。实际运行次序优先启动慢场景，最终清单仍按注册顺序呈现。局部 `--only`、旧别名、空选择拒绝和注册表一致性检查沿用原行为。

新增场景默认不允许并行，整组随即恢复串行。声明允许之前，须确认场景不会盘点其他任务的宿主进程，且材料、台账、技能副本、浏览器状态与服务收尾均独立。

## 失败、中断与计时

fork 继承既有进程组和锁描述符；外部验证不能在尚有任务执行时提前取得原资源锁。父进程收到中断时，先通知登记的任务运行 `finally` 收尾，再有界回收；不能把未完成任务变成通过。任务退出码非零、缺失或不匹配的输出都导致整体非成功，其他已完成结果照常保留。

组执行墙钟取父进程实际区间，逐用例与各任务耗时是累计值，可能重叠。报告不能把累计耗时冒充等待时间。入口版本为 2，选测策略为 9；环境 `config_summary.verification_execution` 区分当前策略与显式串行，执行组的 `execution` 保存实际调度。不同执行方式不能用于同环境证据复用，性能实验的前后比较须明确披露这一控制变量。

## 回退

```bash
AE_VERIFY_SERIAL=1 python3 verify.py run --group all --no-reuse
```

此命令保留完整单元、服务安全与完整浏览器，恢复顺序执行。`python3 -m unittest discover tests` 仍按旧方式执行；浏览器直接入口同样接受 `AE_VERIFY_SERIAL=1`。无需修改或删除测试。性能目标、独立审查、Python 3.9 / 3.12 完整 CI 和最终浏览器验收均保留。
