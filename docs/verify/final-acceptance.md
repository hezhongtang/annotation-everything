## 全流程与剩余验收

日常开发先执行相关组，独立审查和 PR 整理读取同输入的有效证据，无新疑点时不额外请求完整回归。当前 `host-state` 组不能自动复用，PR / CI 门禁必须实际执行；不能通过放宽复用规则制造「零重跑」。纯安全自检可演示 development → review → manual 的同会话引用，实际执行数与引用数分别记录。

未知改动、脏工作区、新增 / 删除 / 重命名未分类测试、输入变化、过期 / 损坏证据继续按现有选测与复用契约处理。H 的确认事件守卫把已确认遗漏或无法界定的影响扩大为实际 `all`，损坏或缺失守卫也保守回退；普通影子遗漏只作为候选。

最终 PR 需核对：完整单元、服务安全、完整浏览器、独立审查、双 Python CI、同输入证据交接及 README 同步。该证据属于最终候选，不由本页的开工实验替代。产品版本、运行时标准库约束、已有审阅协议和合成数据边界保持不变；本项不发版。

父规格关闭前仍需维护者明确处理以下两项：

1. 语言案例 41.160 秒未达到 30 秒目标，须继续优化或明确调整规格。
2. 等价覆盖的完整单元 / 浏览器前后各 3 个可比较样本不足，25% 改善未被证明。须补足证据或提交测量与瓶颈说明，由维护者决定目标；不能以测试数量下降或跨环境比较替代。
