# Remotion 与 HyperFrames 的视频批注和 Agent 改稿

调研日期为 2026 年 11 月 21 日。本文的 HyperFrames 指 HeyGen 的 HTML 视频框架。核查依据为 GitHub 固定提交中的实现、公开发布记录和维护者文档。本次做了静态核查，两个引擎在 annotation-everything 中的实际改稿和重渲染仍待实机验证。

## 两个可用于现有视频工程的仓库

**需要逐条验收，首选 Lampo。需要在本机把两种引擎的成片都交给 Agent 改，FrameJam 也能完成一轮又一轮的交接。** 这两条路径都允许沿用原工程。审阅工具保留人看到的那一版，能访问源码的 Agent 负责找到修改位置，并用工程自己的渲染命令交回新版。[Lampo 的 Agent 协议](https://github.com/lampo-vr/lampo/blob/9c366adfbfd678528e55128c407089ab0017ad71/docs/agents.md#L9-L27) · [FrameJam 的改稿指引](https://github.com/moritzkremb/framejam/blob/bc45364aff90ba931d350e931291940fdc6e604c/skills/framejam/SKILL.md#L122-L144)

## 对 annotation-everything 的建议

第一版可以共用一个视频审阅入口，让 Remotion 和 HyperFrames 各自渲染。现有 HTML 对照页会停用脚本，直接把 HyperFrames 合成当报告页导入会丢失脚本驱动的动画。项目已有会话绑定、显式提交批次、逐条处理说明和停在待复核的流程。新增工作的重点是让每条意见既能找到原版画面，也能跳到新版中实际修改的位置。[HTML 对照页的加载规则](../../skill/annotation-everything/references/formats.md#报告-html) · [现有功能](../../README.zh-CN.md#功能) · [批次与逐条复核约定](../../skill/annotation-everything/references/protocol.md#submission-requirements-and-stop-conditions)

1. **批注时保留原始证据。** 每条记录绑定成片版本、帧率、起止帧，按需要保存归一化点位或框以及标记帧。批注同时关联源工程与合成或场景 ID，有可靠定位时再附序列、元素标识和源码位置。只有成片也能批注，自动改源需要 Agent 能访问相应工程。
2. **交回新版时逐条挂回原意见。** Agent 在原批注 ID 下写明改动、修改版本和新版位置。版式意见附前后帧，节奏、转场或音频意见附可播放的小段。遇到镜头移动或删除，保留旧位置与图像。对应关系不确定时，提示审阅人重新定位。审阅人在原条目上通过或退回。
3. **用两部合成短片验收同一条链路。** 两个引擎各做一部 30 fps 短片。在 V1 第 96 帧框住遮挡图标的字幕，再对 4 至 6 秒的音乐留一条意见。让同一批次交给现有 Agent，改源码、重渲染，并在片头加 12 帧。打开 V2 时，字幕批注应能从旧第 96 帧对到新第 108 帧，音乐意见能试听平移后的 4.4 至 6.4 秒。审阅人通过字幕、退回音量后，下一轮只继续处理音量，前一轮证据仍可回看。这是建议的验收用例。
