# 处理分析轮次

先遵守 [共用安全与协议](protocol.md)。分析复用这份审阅的接收方绑定，但与改稿批次分开排队。只有审阅人可以发起分析；Agent 负责开题和继续追问。分析不直接改报告。

下文 `$S` 是本技能的 `scripts` 目录，`$R` 是本次审阅目录。审阅人可以从批注、某一页或空白焦点问题发起；没有源批注的分析不创建占位批注。Agent 只能用 `notes.py suggest-analysis "$R" NOTE_ID --reason "建议原因"` 给未处理批注加建议，由审阅人决定是否发起。

## 接收与读取

等待机制支持通知时，使用 `python3 "$S/notes.py" wait "$R" --events analysis --locale zh-CN`。没有显式参数的等待进程只接收改稿批次，不会领取分析轮次。两个队列统一按交出先后领取，一次处理一项；精确领取遇到更早的队首时返回 3，先完成更早的项，不能绕过它。

桌面事件到达时，先运行提示中给出的 `wakeup.py ack ...`，然后运行对应领取命令。分析用审阅内唯一的轮次号，批次用批次序号，两者不能混用：

```bash
python3 "$S/notes.py" claim "$R" --events analysis --round N --by Agent
python3 "$S/notes.py" analysis "$R" --round N --json
```

保留领取结果中的 `baseRev`。完整上下文包含焦点问题、当前路径上的决策、本轮条目、审阅人原话回答、相关假设及其在线上的确认状态、查证事实、搁置问题，以及发起分析时的源批注副本（如有）。先读这些记录再继续，不依赖聊天摘要补全审阅人的意思。

若由 `wait --events analysis` 返回，该轮已经领取，直接读取上下文，不要重复领取。精确领取返回 3 时，可用 `claim "$R" --events analysis` 接收真正的队首，再按返回的 `event` 分流；不能先处理尚未领取的目标轮次。

## 写回下一轮

结构提议保存为 JSON 列表。每题必须包含不重复的 `key`、完整 `text`、自然叫法 `short`、带稳定 `id` 和 `label` 的 `options`、以及属于这些选项的 `recommend`；挂在已有问题下时附 `parent: {node, option}`。新增的问题只有经审阅人在轮次里确认后才进入问题树；决策由系统根据回答产生，不由 Agent 写入。

旧列表形式继续支持。需要提交假设或查证事实时，文件改为对象：`{proposals: [], assumptions: [], facts: []}`。假设使用 `{key, text, decisions: [决策标识]}`，事实使用 `{key, text, source?, node?}`。`key` 用于识别同一条记录，已经存在的原文不能借重复写回来改写。事实保留完整出处；假设需在下一轮由审阅人确认或不认同，不认同不等于推翻。

结构提议默认 `op: "add"`。拆分使用 `op: "split"`、单个 `targets` 和至少两个 `replacements`；合并使用 `op: "merge"`、至少两个 `targets` 和一个 `replacements`；作废使用 `op: "void"` 和 `targets`。替代问题沿用新增问题的字段。目标必须在当前选择枝上，同轮不能重复引用；替代问题不能挂在将作废的枝下。所有结构变化都等审阅人确认后生效，拒绝的提议不要重复提出，历史问题和决策不删除。

```bash
python3 "$S/notes.py" analysis-writeback "$R" --round N --base-rev REV --proposals questions.json --note "本轮分析说明"
```

`--proposals -` 从标准输入读 JSON。没有新问题时传空列表；未答的有效问题由系统带入下一轮。问答和说明保留全文，不用聊天摘要替换原文。只写回领取过的轮次，保留基线校验；被拒绝时读取当前上下文并报告原因。

回答包含用推荐答案、选项、自由文本、先搁置和需要查证。自由文本按原话读取；搁置的问题不再作为前沿追问。查证请求的 `allowExternal` 默认是 `false`，只有明确的布尔值 `true` 才允许外部资料；未获允许时只查这份审阅的原始材料。把查证结果写进 `facts`，再由审阅人作答。一份审阅可以有多个分析，暂停分析中已经交出的轮次仍需正常处理；切换焦点不使领取的基线失效。

分析轮次不调用批注的 `resolve` / `done`，不改上游报告或讲稿，不重建对照页。需要查证默认只查审阅的原始材料，外部资料须审阅人在该题明确允许。由审阅人在页面上把结论转成草稿并确认；确认后的批注才进入正常「交给 Agent 改稿」流程，转出本身不会自动提交改稿。

有已保存的桌面事件绑定时，写回后保留服务，结束当前轮处理，等待下一事件。使用经过核实的宿主通知机制时，再次启动带 `--events analysis` 的等待命令。不要把运行中的进程或领取成功当作聊天已收到的证据。
