# 各 Agent 的对应机制

[English](agent-mechanisms.en.md)

命令、文件和退出码对所有 Agent 一致。首次配置等待、调用批注技能、分派子代理或设置处理人时，按下表选择当前宿主提供的机制。权限、阶段停止和安全要求以[共用安全与协议约束](protocol.md)为准；完整操作顺序见[中文操作流程](workflow.zh-CN.md)。

| 环节 | Claude Code | 其他 Agent |
|---|---|---|
| 等待与唤醒 | `serve.py` 和 `notes.py wait` 都用后台方式运行（Bash 的 background）。宿主的后台任务完成通知会在 `wait` 结束时唤醒会话；读取退出码和输出后处理收到的批次。 | 宿主提供后台完成通知时可使用同样的等待方式。否则循环运行 `notes.py wait 审阅目录 --timeout 30`（超时返回 3），或定时运行 `notes.py claim 审阅目录`（收到提交时输出 JSON 并返回 0，没有提交时返回 3）。需要由宿主或仍在运行的会话安排下一次轮询。支持外部事件的宿主也可接入 `serve.py 审阅目录 --on-handoff "命令"`。 |
| 调用技能 | 用 Skill 工具按名称调用批注指定技能和适用的常驻技能。 | 使用宿主提供的技能加载机制；按名称找到对应 `SKILL.md` 并执行。技能不存在时说明缺失，并按共用协议继续处理。 |
| 子代理分派 | 本批允许派发时，用 Agent 工具分派；宿主支持时通过 `model` 选择成本较低的模型初改、能力较强的模型复核。 | 本批允许派发时，用宿主的子代理或多会话机制接力；没有该能力时由主会话亲自处理。 |
| `--by` 处理人 | `notes.py` 检测到非空 `CLAUDECODE` 环境变量时，缺省记为 `claude`。 | 没有该环境变量时，缺省记为 `agent`。 |

`--by` 可指定名字，如 `--by 初改`、`--by 复核`。按角色明确命名，页面与处理痕迹才能区分各阶段的处理人。

## Codex 桌面：审阅级事件接入

用户要求网页提交后自动处理时，Agent 执行以下步骤。用户无需修改 Codex 配置。

1. 读取 `python3 $S/wakeup.py status 审阅目录`。已有绑定时沿用它，不把别的聊天或 Agent 自动改成新接收方。
2. 首次绑定：`python3 $S/wakeup.py bind 审阅目录`。从当前宿主的 `CODEX_THREAD_ID` 取得聊天身份；环境没有该字段时，用已确认的当前聊天标识显式传 `--thread UUID`。命令检查本机桌面 socket 和聊天 owner，把绑定保存到审阅旁的私有文件。`--by Codex` 仅是署名，不参与路由。
3. 正常运行 `python3 $S/serve.py 审阅目录`。已有旧服务时先确认该进程属于本审阅且不打断其他人的处理，再停止、重启。后续普通重启自动恢复绑定，不需要重新传回调。自定义 `--on-handoff` 与保存的绑定冲突时拒绝启动；确需改接收方式时，用户决定后运行 `wakeup.py unbind 审阅目录` 并重启。
4. 事件消息送达后，先执行消息中给出的 `wakeup.py ack ...`，再按明确的批号 `notes.py claim --seq N --by Codex`。读接收后的用户要求，按原协议改稿和收尾。绑定模式不另开认领型 `wait`，也不创建定时任务。其他聊天不能通过新版 CLI 抢先 claim。
5. 验收包括真实空闲会话：上一轮已完成后，在合成审阅网页提交，确认聊天产生新的处理轮次，回写 ack、逐条处理和 done；正常重启同一服务后再次验证。忙碌会话接收消息、owner 查询成功或命令退出 0 均不足以证明空闲唤醒成功。

`wakeup.py status` 分开显示 `accepted`（桌面接受投递）和 `received`（聊天实际执行接手确认）；网页也显示这两个阶段。`failed` 可以在服务重启或用户再次提交时重试。`sending` 遭中断、或发送后丢失确认，会保留为 `unconfirmed`，须先核对聊天和批次，不能盲目重发。服务启动仅恢复待接收/待复核提交，不抢占他人已认领的批次。

该适配器使用桌面现有本机 IPC，不改 Codex 全局配置、权限、模型或应用文件，不启动另一个 CLI Agent。IPC 不是稳定公开接口；当前验证环境为 macOS 桌面 26.1027.51404。桌面未运行、目标聊天无 owner 或协议不兼容时，明确报告接入失败并保留批注，不退回假成功。绑定仅适用于原审阅身份及目录；移动或复制后须核对并重新绑定。`unbind` 只解除接入，保留批注与投递历史。

钩子的输入、运行目录和快照处理规则见[中文流程第 2 节](workflow.zh-CN.md#2-启动服务并挂起等待)。分派前按[第 5 节](workflow.zh-CN.md#5-先改后审两段流程)传递已接收要求、批号和技能，并保留主会话收尾与用户确认的阶段边界。
