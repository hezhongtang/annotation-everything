# 各 Agent 的对应机制

[English](agent-mechanisms.en.md)

命令、文件和退出码对所有 Agent 一致。首次配置等待、调用批注技能、分派子代理或设置处理人时，按下表选择当前宿主提供的机制。权限、阶段停止和安全要求以[共用安全与协议约束](protocol.md)为准；完整操作顺序见[中文操作流程](workflow.zh-CN.md)。

| 环节 | Claude Code | 其他 Agent |
|---|---|---|
| 等待与唤醒 | `serve.py` 和 `notes.py wait` 都用后台方式运行（Bash 的 background）。宿主的后台任务完成通知会在 `wait` 结束时唤醒会话；读取退出码和输出后处理收到的批次。 | 宿主提供后台完成通知时可使用同样的等待方式。否则循环运行 `notes.py wait 审阅目录 --timeout 30`（超时返回 3），或定时运行 `notes.py claim 审阅目录`（收到提交时输出 JSON 并返回 0，没有提交时返回 3）。需要由宿主或仍在运行的会话安排下一次轮询。支持外部事件的宿主也可接入 `serve.py 审阅目录 --on-handoff "命令"`。 |
| 调用技能 | 用 Skill 工具按名称调用批注指定技能和适用的常驻技能。 | 使用宿主提供的技能加载机制；按名称找到对应 `SKILL.md` 并执行。技能不存在时说明缺失，并按共用协议继续处理。 |
| 子代理分派 | 本批允许派发时，用 Agent 工具分派；宿主支持时通过 `model` 选择成本较低的模型初改、能力较强的模型复核。 | 本批允许派发时，用宿主的子代理或多会话机制接力；没有该能力时由主会话亲自处理。 |
| `--by` 处理人 | `notes.py` 检测到非空 `CLAUDECODE` 环境变量时，缺省记为 `claude`。 | 没有该环境变量时，缺省记为 `agent`。 |

`--by` 可指定名字，如 `--by 初改`、`--by 复核`。按角色明确命名，页面与处理痕迹才能区分各阶段的处理人。

钩子的输入、运行目录和快照处理规则见[中文流程第 2 节](workflow.zh-CN.md#2-启动服务并挂起等待)。分派前按[第 5 节](workflow.zh-CN.md#5-先改后审两段流程)传递已接收要求、批号和技能，并保留主会话收尾与用户确认的阶段边界。
